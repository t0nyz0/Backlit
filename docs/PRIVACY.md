# Privacy and storage

Backlit has no analytics SDK or developer-operated service. Its core modes work without an account.

- Preferences use the app's macOS defaults domain, `local.backlit`.
- Hardware recovery, agent metadata, and configuration backups live in `~/Library/Application Support/Backlit`. These files are local and are not encrypted by Backlit. A hook-configuration backup may contain sensitive pre-existing agent settings; do not share it.
- Hook commands extract only a session ID, validate it, and pass it alongside a fixed agent/state to the app. Backlit stores a hash-derived filename, agent, state, and timestamp. It does not read transcripts or receive prompts, tool input, or output. Raw session IDs are not written to event files.
- Music uses a private, unmuted Core Audio process tap on macOS 14.2+, after user action and macOS authorization. It creates no screen/window capture session and never changes the default audio device. Its temporary private aggregate device and tap are destroyed on stop or setup failure. On macOS 14.0–14.1, the fallback uses ScreenCaptureKit with only an audio output registered. No captured material is stored or sent anywhere. No microphone source is used.
- Trackpad uses native MultitouchSupport callbacks from trackpad devices only. It reads contact path/state and optional button-state changes, never coordinates or touch buffers. Input is not recorded, and callbacks stop when another mode is selected or the light is disabled. Global screen touch remains unsupported.
- The Home Assistant key is a random 256-bit value in Keychain. Sharing starts off. Automatic restoration only reuses that key without prompting or creating a replacement; an unavailable HA credential does not disable a healthy MCP connection, which stays loopback-only. Explicit connection setup and key replacement retain native authorization. Local-network access is a separate setting. The API returns light/battery/agent state, not prompts or code.
- The optional ambient override requires system administrator authorization. It saves prior root-domain preferences under `/var/db/local.backlit` and changes only its two brightness-limit keys. Restoring those limits also requires administrator authorization.
- A closed-lid watchdog owns an app-created lease and recovery marker. It monitors the parent process, elapsed closed time, battery, and thermal state; it releases its power changes on normal shutdown. Force-killing both the app and watchdog is a separate recovery case, not a guaranteed clean exit.
- Optional typing response observes key-down timing only after explicit permission; it does not read characters or key codes, identify apps, or store input. Secure Input can suppress it.
- The Sparkle updater is dormant until a trusted HTTPS feed and pinned public signing key are included in the app bundle. Manual update checks disable automatic checks/downloads and system profiling. This build has no configured feed/key and does not make an update request. Signed feeds and pre-extraction archive verification are required; no silent update or app license check is included. GitHub/help links still open externally.
- The optional Stream Deck plugin uses fixed local Backlit links for power, brightness and behavior. It does not receive the Home Assistant pairing key.
- Regular global shortcuts use registered key combinations rather than a general keyboard monitor. The recorder reads a chosen chord only while its sheet is open and stores that binding. The separate experimental Shift + hardware-brightness filter starts off. After explicit Accessibility setup and an Input Monitoring preflight, it examines only auxiliary brightness events and their modifiers, phase and repeat bits; it never reads characters, records keystrokes or logs event payloads. Other keys pass through. It stops on permission/tap failure and does not request permissions during startup. It does not post synthetic events or write display brightness. Physical suppression depends on the keyboard/OS and remains unverified.
- AI control starts off and has independent Status only / Allow light changes permissions. Its random key is stored separately from the Home Assistant key in Keychain. The local stdio process reads that key without requesting permission, creating a key, or opening a GUI. It only contacts Backlit's loopback API, refuses redirects and proxies, and has no direct light, audio or input control. No tool calls/results or credentials are logged. Your assistant can send returned light status to its own model provider; Backlit itself sends no cloud requests for MCP. Turn AI access off to stop these connections. Replacing the key invalidates the previous bearer key; legitimate local clients can read the replacement. It does not identify or block an individual assistant.

To remove Backlit: disable the brightness override if enabled, disconnect agent hooks, turn off login launch and sharing, then quit with restoration and remove the app. Keep recovery records if an operation failed; deleting them is not restoration. A deliberately retained off state needs restoration before uninstalling if you want the prior logo behavior back.
